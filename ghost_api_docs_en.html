01

Overview

GHOST INTERFACE is a local control panel that combines webcam input, MediaPipe hand landmark detection, gesture classification, and system command execution. The public API is intentionally small — it serves a web dashboard, streams the annotated camera feed as MJPEG, exposes the latest detected gesture, and checks camera availability.

03

Authentication

⚠ No authentication is implemented. Because the application can execute local OS-level commands (mouse movement, clicks, volume, keyboard shortcuts), it must only be exposed on a trusted local machine. Do not bind it to a public network interface without adding authentication and command-safety controls.

04

Endpoints

GET / Main dashboard ▼

Returns the main GHOST INTERFACE dashboard page. The dashboard lets a user select a local document or image, start the gesture interface, view the live camera feed, and see detected gesture feedback.

Request
GET http://127.0.0.1:5000/
Response
200 OK Content-Type: text/html
cURL
curl http://127.0.0.1:5000/
ℹ The page loads static/css/style.css and static/js/main.js. The frontend creates an <img src="/video_feed"> element and polls /api/status every 500 ms.
GET /video_feed Live MJPEG camera stream ▼

Streams annotated webcam frames as MJPEG. Each request opens a new CameraStream, reads frames from camera index 0, detects hand landmarks, draws overlays, updates the latest gesture state, and yields JPEG frames in a multipart response.

Recommended HTML Usage
<img src="/video_feed" alt="Live camera feed">
Response format — each part
--frame Content-Type: image/jpeg <jpeg-bytes>
⚠ While the stream is active, the server may execute OS commands when a recognized gesture passes its cooldown check. If /video_feed is not being consumed, gesture detection does not run.
✓ If the webcam cannot be opened, a fallback JPEG frame containing a camera-not-found message is returned instead of crashing the route.
GET /api/status Latest gesture + event log ▼

Returns the latest detected gesture name and a recent event log. The frontend uses this endpoint to update the "Last Gesture" panel every 500 ms.

Request
GET http://127.0.0.1:5000/api/status
● Example response
{ "gesture": "thumb_up", "log": [ { "time": "16:41:20", "gesture": "thumb_up" }, { "time": "16:41:13", "gesture": "open_palm" } ] }
FieldTypeDescription
gesturestringLatest detected gesture. Defaults to unknown before any gesture is detected.
logarrayMost recent 15 gesture execution events, newest first.
log[].timestringLocal server time in HH:MM:SS format.
log[].gesturestringGesture name that triggered a command.
ℹ The server stores up to 30 gesture events internally; the API returns the latest 15, reversed so the newest appears first. State resets on Flask process restart.
GET /api/camera/status Check camera availability ▼

Checks whether camera index 0 can be opened. Creates a short-lived OpenCV VideoCapture, calls isOpened(), releases it, and returns the result.

Camera available ✓
{ "ok": true }
Camera unavailable ✗
{ "ok": false }
ℹ Call this endpoint before starting a session to warn users about camera availability before they load /video_feed.

06

Configuration

Gesture-to-command behavior is controlled by config.json at the project root.

config.json — current defaults
{ "gestures": { "open_palm": "mouse_move", "fist": "left_click", "thumb_up": "volume_up", "thumb_down": "volume_down", "pinch_out": "zoom_in", "pinch_in": "zoom_out", "pointing_up": "left_click", "swipe_right": "next_page", "swipe_left": "prev_page" }, "app_to_open": "notepad", "volume_step": 5, "zoom_step": 0.1 }

Supported Commands

CommandBehavior
mouse_moveMoves the mouse to normalized hand coordinates.
left_clickPerforms a left mouse click via pyautogui.
volume_upIncreases system volume by volume_step.
volume_downDecreases system volume by volume_step.
zoom_inSends Ctrl + +.
zoom_outSends Ctrl + −.
next_pageSends the right-arrow key.
prev_pageSends the left-arrow key.
open_appOpens the configured application (not mapped to any gesture by default).
⚠ open_app exists in CommandHandler but is not mapped to any gesture in the current config.json.

Error Handling

ScenarioBehavior
config.json missingFalls back to empty gesture mappings, notepad, volume_step=5, zoom_step=0.1.
config.json invalid JSONSame fallback defaults as above.
Unknown gestureSilently ignored — no exception raised.
Missing hand coords (mouse move)Mouse movement is skipped.
Webcam fails in /video_feedReturns a generated fallback JPEG frame.
Webcam fails in /api/camera/statusReturns {"ok": false}.
Command execution errorLogged by CommandHandler; server route continues running.
09

Recommended Future Additions

These additions would make the API easier to operate and test without changing the current public behavior.

GET /api/config

Return the currently active gesture-to-command mappings and settings.

PUT /api/config

Update gesture mappings and settings safely at runtime without restarting the server.

POST /api/commands/test

Trigger a named command in a controlled test mode without requiring an active video stream.

GET /api/stream/status

Return FPS, frame count, landmark count, and stream running state.

POST /api/session/start  ·  /api/session/stop

Start and stop detection independently from the browser image stream and release camera resources explicitly.

⚠
Current API Limitations
  • No authentication or authorization
  • No POST endpoints for runtime configuration changes
  • Video stream is locked to camera index 0
  • Status API does not expose FPS, landmark count, or stream health
  • Gesture detection only runs while /video_feed is being consumed
  • In-memory state resets on every Flask process restart
